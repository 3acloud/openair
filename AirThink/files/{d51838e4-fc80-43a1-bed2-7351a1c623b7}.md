## 产品与设计依据

| 项目 | 本次定义 |
| --- | --- |
| 产品品类 | 企业仓储库存 SaaS 的补货工作台 |
| 目标用户 | 仓库主管 |
| 主要任务 | 发现低库存 → 选择 SKU → 核对供应商交期 → 生成并移交补货草稿 |
| 内容 | SKU、商品规格、可用库存、安全库存、在途数量、预计到货日、供应商、建议补货量 |
| 品牌约束 | 冷静蓝灰、左导航、高信息密度；表格是视觉主角 |
| 设计范围 | 已有方向深化；未提供原始截图、品牌资产或组件文件，细节依据上述约束推导 |

使用深蓝灰导航、浅灰画布和蓝色操作强调，红色与琥珀色仅表达风险，并配文字标签。主工作区同时展示 8 个 SKU；数量右对齐，SKU 与商品规格上下排列，选中行与当前核对行有不同的视觉反馈。顶部指标采用紧凑横条，避免营销式大卡片。

右侧核对栏保留供应商、在途采购单、原承诺到货日、最新预计到货日、更新人及更新时间，让仓库主管在同一画面判断风险。草稿状态按供应商拆分，突出“保存草稿并交采购核对”，生成入口转为弱化的“已生成草稿”状态。

## 补货判断与关键状态

设计采用以下业务假设：可用库存已扣除预占；缺口为 `max(0, 安全库存 − 可用库存 − 可及时到货的在途数量)`，再按最小采购量和采购倍数向上取整。本稿采取保守口径，延期或交期未确认的在途不抵扣。正式落地时需确认企业的需求日期与交期判定规则。

以 `PKG-TAPE-060` 为例：安全库存 80 件，可用 16 件，在途 40 件预计 10-13 到货，晚于预计断货日 10-10。因此缺口为 64 件，按 40 件采购倍数取整为 80 件。新增补货按标准交期预计 10-12 到货，仍晚于要求到货日，草稿提示采购专员核实加急排产和物流。

选中的 3 个 SKU 拆成 2 张供应商草稿。每个 SKU 保留自身采购单位；“260 采购单位”是各 SKU 数量的汇总，不表示它们可以换算成相同件数。“已有待确认草稿”与“本次生成”分别标注，区分历史存量和本次工作。

所有 SKU、供应商、库存、单号、日期和人员均为拟真模拟数据；未使用真实企业库存，也未实际创建采购单。
