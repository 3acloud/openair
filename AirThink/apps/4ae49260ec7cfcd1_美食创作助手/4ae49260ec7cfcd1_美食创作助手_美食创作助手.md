# 美食创作助手
	这是一个面向泛美食账号的内容创作网页应用，包含首页、创作工坊、作品库三个页面。整体采用暖厨光影主题：米杏渐变背景（#FFF8F1 到 #F3E0C8），导航与主按钮使用焦糖橙（#C45C26），点缀椒盐深棕（#2C1810）与奶油白卡片；标题使用衬线字体，正文使用圆润 sans-serif；卡片带轻微食物蒸汽感阴影与悬停上浮，按钮有锅气热感的微光过渡。不包含用户登录页面。
	页面顶部导航栏，使用焦糖橙到深焙棕的横向渐变
		左侧显示Logo（一只简笔砂锅/木勺图标）和「美食创作助手」
		右侧显示标签：首页、创作工坊、作品库
	首页
		主标题：美食创作助手
		说明：按菜名创作、按人群场景推荐、一键规划一周选题；确认方向后再生成步骤图文与成稿，改到你满意为止
		下方三个并列快捷入口大卡片（点击均跳转「创作工坊」并预选对应创作类型）
			指定菜品：已有菜名，整理用料步骤并给出文案角度
			推荐菜品：按人群、节气或场景推荐 3 至 5 道菜
			一周选题：输出 7 天荤素搭配清单，确认后再逐篇创作
		主按钮：开始一道新菜，点击跳转到「创作工坊」，当前行设为 0 并清空表单
		接下来是并列的四个统计小卡片
			全部作品数
				API名称:GetRecordCount,数据源:美食创作/默认表格
			指定菜品数
				API名称:GetTableCSV,数据源:美食创作/默认表格,字段:[创作类型]
				筛选创作类型为「指定菜品」的记录计算数量
			推荐菜品数
				API名称:GetTableCSV,数据源:美食创作/默认表格,字段:[创作类型]
				筛选创作类型为「推荐菜品」的记录计算数量
			一周选题数
				API名称:GetTableCSV,数据源:美食创作/默认表格,字段:[创作类型]
				筛选创作类型为「一周选题」的记录计算数量
		接下来是最近作品：以卡片形式显示最近 5 条
			API名称:GetTableCSV,数据源:美食创作/默认表格,字段:[创作类型,菜名,目标人群,主题场景,文案方向,确认与修改意见]
			卡片封面区展示该行创作结果中的首张图片（若有）：先 GetRecordRow 定位行号，再 GetCellValue 取「创作结果」，从 Markdown 中提取第一张图片链接；无图时显示对应创作类型的插画占位
			卡片正文显示：创作类型徽章、菜名（空则显示主题场景或「未命名选题」）、目标人群、主题场景、文案方向摘要
			点击卡片查看详情（打开详情抽屉，Markdown 渲染完整创作结果）
	「创作工坊」页面
		左上显示大标题：创作工坊
		说明：选好类型、填好方向，把火候交给助手；没有明确确认前，助手会停在当前节点等你点头
		右上按钮组
			按钮：作品库，跳转到「作品库」页面
			按钮：+ 新开一张白盘，清空表单与结果区，当前行设为 0
		页面采用左右分栏（小屏上下堆叠）
		左侧为创作表单区
			顶部以三张可选中的类型卡片代替下拉框，必须三选一：指定菜品、推荐菜品、一周选题；选中态用焦糖描边与浅橙底
			表单标题:美食创作,表:美食创作,字段:[{字段名:创作类型,类型:单选项,可选项:指定菜品,推荐菜品,一周选题},{字段名:菜名,类型:文本},{字段名:目标人群,类型:文本},{字段名:主题场景,类型:文本},{字段名:文案方向,类型:文本},{字段名:确认与修改意见,类型:文本}]
			字段名只能使用表定义中的上述字段，不得编造 ID、创建日期等字段
			按创作类型动态展示与提示，未展示的字段提交时传空字符串，不得把空值当成用户已确认
				指定菜品：显示菜名（必填，占位「例如：番茄牛腩」）、目标人群、主题场景、文案方向、确认与修改意见；提示优先从下厨房整理成品图、步骤图、用料及做法，先给 2 至 3 个文案角度，确认方向后再写初稿
				推荐菜品：显示目标人群、主题场景、菜名（选菜后回填）、文案方向、确认与修改意见；提示将推荐 3 至 5 道菜并给出适合原因与一句话卖点，等待选菜
				一周选题：显示目标人群、主题场景、文案方向、确认与修改意见；提示先输出 7 天菜品、角度及卖点清单，注意荤素、难度与餐次，确认清单后再逐篇创作
			「文案方向」在尚未确认角度时允许留空；用户从结果中选定某一角度后填入再继续
			「确认与修改意见」用于选菜、确认清单、换第几个菜谱、修改口吻/步骤/标题、或要求连续创作；占位示例：「选第 2 道，按家常暖胃方向写初稿」或「第 3 步火候再写具体一点」
			主按钮：开火创作
				仅当创作类型已选择，且（指定菜品时菜名非空，或推荐菜品/一周选题时目标人群或主题场景至少一个非空，或确认与修改意见非空）时启用
				点击使用 SubmitRecord 提交，data 为「美食创作」，payload 为 json 文本，仅包含：创作类型、菜名、目标人群、主题场景、文案方向、确认与修改意见
				提交后当前行是 1
				「创作结果」为指令流字段，不由用户填写，SubmitRecord 后由后台 AI 异步生成
			次按钮：保存修改
				仅当当前行>=1 时启用
				依次 SetCellValue 更新当前行的创作类型、菜名、目标人群、主题场景、文案方向、确认与修改意见，不调用 SubmitRecord，不重新触发生成
			次按钮：按意见再来一版
				将当前表单字段（含最新确认与修改意见）再次 SubmitRecord 作为新记录，用于确认方向、选菜、换菜谱、修改或连续创作；提交后当前行是 1 并进入轮询
		右侧为出餐结果区
			顶部标题：出餐结果
			右上角两个小按钮：〈 和 〉
				API名称:GetRecordCount,数据源:美食创作/默认表格
				当前行初始是 0
				当前行<=1 时〈不可操作
				当前行>=RecordCount 时〉不可操作
				点击〈读取上一行，点击〉读取下一行
				用 GetCellValue 逐字段回填表单：创作类型、菜名、目标人群、主题场景、文案方向、确认与修改意见，并用 Markdown 主题显示该行创作结果
			提交后开始轮询
				轮询标题:美食创作,表:美食创作,字段:创作结果,输出到:出餐结果,等待消息:炉火正旺，正在备料、翻炒和摆盘…
				轮询 API名称:GetCellValue,数据源:美食创作/默认表格,字段名:创作结果,行号:当前行
				指令描述未要求 JSON 输出，因此轮询「创作结果」本身，直到返回非空文本
			出餐结果使用 Markdown 主题呈现完整文本，混排短文、成品图与步骤图；图片若为全局文件名则渲染为 https://www.ithinkair.com:3031/download/全局文件名 ，若已是可访问链接则直接显示
			多篇内容展示在同一份 Markdown 中，不以目录代替正文
			当前行为 0 且未提交时，结果区显示空态插画与一句「选好类型，我来掌勺」
		表单与结果区下方提供一条流程提示条，随创作类型变化，例如：指定菜品 → 整理图文步骤与 2-3 个角度 → 你确认文案方向 → 写初稿 → 按修改意见打磨
	「作品库」页面
		左上显示大标题：作品库
		说明：所有已提交的美食创作记录，点击卡片继续改稿或查看成稿
		右上是按钮：+ 开始创作，跳转创作工坊并清空表单，当前行设为 0
		搜索框：可按菜名、目标人群、主题场景、文案方向、确认与修改意见关键词过滤
		筛选器：按创作类型筛选（全部 / 指定菜品 / 推荐菜品 / 一周选题）
		主体以卡片网格展示，不使用普通数据表作为主视图；卡片字段与表单字段一致，以便点击后进入编辑
			API名称:GetTableCSV,数据源:美食创作/默认表格,字段:[创作类型,菜名,目标人群,主题场景,文案方向,确认与修改意见]
			每张卡片显示：创作类型徽章、菜名或主题场景标题、目标人群、文案方向一行摘要、确认与修改意见一行摘要
			封面图：GetRecordRow（payload 为可唯一定位的字段名/值，如 菜名/该行菜名，若菜名为空则用 主题场景/值 或 确认与修改意见/值）得到从 1 起计的行号，再 GetCellValue 取创作结果并抽取首图
			每张卡片操作：查看成稿、继续创作、删除
				查看成稿：弹出详情层，GetCellValue 读取创作结果，以 Markdown 主题展示；图片按下载链接渲染
				继续创作：当前行设为该行号，GetCellValue 逐字段回填创作工坊表单并跳转，结果区同时渲染该行创作结果，用户可补充确认与修改意见后点「按意见再来一版」
				删除：调用 DeleteRecord，data 为 美食创作/默认表格，payload 为行号.toString()，删除后刷新卡片列表与首页统计
			点击整张卡片等同于「继续创作」
		详情层底部提供「把这版再打磨」快捷框，绑定确认与修改意见，提交时 SubmitRecord 新记录（带上原创作类型、菜名、目标人群、主题场景、文案方向及新的确认与修改意见），然后跳转创作工坊轮询新结果
	详情与列表的数据约定
		查看字段详情一律 GetCellValue
		新建用 SubmitRecord，提交后当前行是 1，并轮询创作结果
		修改已有记录的用户字段用 SetCellValue，payload 格式为 字段名/行/值
		GetTableCSV 不含标题行；逗号分隔字段名必须是本表已定义字段
		布尔值若出现用「是」或「否」（本表无布尔字段）
		不要为不存在的 ID、创建日期等字段占位或显示
	各页面使用统一的暖厨主题，卡片与按钮均需悬停反馈；首页最近列表、作品库卡片、详情层的查看/继续/删除/开火创作/保存修改/按意见再来一版/新开一张白盘以及〈〉翻篇，对应功能必须全部实现。
