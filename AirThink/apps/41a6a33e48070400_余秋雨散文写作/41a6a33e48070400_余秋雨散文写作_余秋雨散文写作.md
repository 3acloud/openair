# 余秋雨散文写作
	这是一个余秋雨式文化散文写作网页应用，包含首页、落笔成章、文稿馆三个页面。不包含用户登录页面。操作按钮对应的功能必须全部实现。
	统一主题：水墨书院。整站如宣纸上的夜读——背景为宣纸米色到浅墨灰的柔和渐变（#F7F1E3 → #EDE4D4），纸纹噪点极淡；导航为深墨色（#1A1A1A）；主文字为墨黑（#2B2B2B）；强调色为朱砂红（#C23A2B）；点缀暗金（#B0894F）与青灰（#6B7280）。标题字体使用 Noto Serif SC / 思源宋体，正文使用柔和衬线。卡片如册页：细线边框、轻微阴影、悬停时如翻纸微抬，题材类型以小印章样式呈现。按钮圆角克制，主按钮朱砂底白字，次按钮墨线描边。阅读区模拟竖栏气息的横排排版，行距疏朗，首字可微放大。禁止花哨动画，过渡缓慢、克制。
	页面顶部导航栏，深墨色背景
		左侧显示印章风格Logo（阴文“秋”字方印）和「余秋雨散文写作」
		右侧显示标签：首页、落笔成章、文稿馆；当前页标签用朱砂下划线标识
	首页
		主标题：余秋雨散文写作
		说明：以景点或历史人物为锚点，用余秋雨式文化散文技法写成篇章，语言典雅、情感克制，融合行走见闻与文化反思。
		主按钮：提笔写下，点击跳转到「落笔成章」页面并清空表单（当前行设为0）
		接下来是并列的六个统计卡片：总篇章数、文化遗址游记、历史人物散文、文明反思、旅行文学、古迹精神探寻
			总篇章数卡片显示全部记录数量
				API名称:GetRecordCount,数据源:散文写作/默认表格
			其余五张题材卡片分别显示对应题材类型的篇章数量
				API名称:GetTableCSV,数据源:散文写作/默认表格,字段:[题材类型]
				按题材类型筛选计数
		接下来是「最近文稿」卡片列表（不要用表格）：显示最近5篇，每张卡片展示写作对象、题材类型（印章）、现场见闻前60字、个人感悟前40字
			API名称:GetTableCSV,数据源:散文写作/默认表格,字段:[写作对象,题材类型,现场见闻,个人感悟]
			提交后新记录在第1行，故按CSV行序取前5条即为最近文稿
			点击任一卡片进入详情：当前行设为该卡片对应行号（CSV行序从1计），跳转「落笔成章」，用GetCellValue逐字段回填表单，并GetCellValue读取「散文」以Markdown主题显示于成篇区
			若无记录，显示空态：「纸素未着一字。去落笔成章。」
	「落笔成章」页面
		左上显示大标题：落笔成章，说明：以一处风景或一个人名为锚，写下见闻与感悟，待墨迹自行蔓延成篇
		右上按钮组：
			按钮：文稿馆，跳转到「文稿馆」
			按钮：+ 新开一张纸，清空表单与成篇区，当前行设为0
		桌面端左右分栏（移动端上下堆叠）：左侧「草稿笺」，右侧「成篇」
		草稿笺为表单
			表单标题:散文写作,表:散文写作,字段:[{字段名:写作对象,类型:文本},{字段名:题材类型,类型:单选项,可选项:文化遗址游记,历史人物散文,文明反思,旅行文学,古迹精神探寻},{字段名:现场见闻,类型:文本},{字段名:个人感悟,类型:文本},{字段名:散文,类型:指令流}]
			表单只显示并允许填写：写作对象、题材类型、现场见闻、个人感悟
			写作对象占位：一座城、一处遗址、一个名字，如「都江堰」或「苏东坡」
			现场见闻、个人感悟使用多行文本
			散文为指令流字段，用户不可手工填写，不出现在可编辑表单项中
			字段名必须使用表定义中的字段名，不得编造ID、创建日期或其他字段
		草稿笺底部主按钮：落笔成篇
			仅当写作对象、题材类型、现场见闻、个人感悟均非空时启用
			当前行为0或新建时：使用SubmitRecord提交，表单数据是json文本，仅包含写作对象、题材类型、现场见闻、个人感悟；提交后当前行是1
			当前行>0且为修改已有记录时：依次通过SetCellValue设当前记录行各字段的值（写作对象、题材类型、现场见闻、个人感悟），不要用SubmitRecord；修改不重新生成散文
		SubmitRecord提交后，必须轮询等待后台AI异步生成结束
			指令描述未要求JSON格式输出，故轮询该指令流字段「散文」
			轮询标题:散文写作,表:散文写作,字段:散文,输出到:成篇区,等待消息:纸上墨痕正慢慢洇开……
			API名称:GetCellValue,数据源:散文写作/默认表格,字段名:散文,行号:当前行
			生成结束后，成篇区用Markdown主题显示散文正文；等待期间成篇区只显示等待消息，不要提前渲染半成品
		成篇区
			顶部横匾显示当前写作对象与题材类型；若当前行为0且未生成，显示「尚未落笔」
			正文以Markdown主题呈现，典雅阅读版式，不显示写作说明
			成篇区右上角按钮：「<」与「>」
				API名称:GetCellValue,数据源:散文写作/默认表格,字段名:写作对象,行号:当前行
				API名称:GetCellValue,数据源:散文写作/默认表格,字段名:题材类型,行号:当前行
				API名称:GetCellValue,数据源:散文写作/默认表格,字段名:现场见闻,行号:当前行
				API名称:GetCellValue,数据源:散文写作/默认表格,字段名:个人感悟,行号:当前行
				API名称:GetCellValue,数据源:散文写作/默认表格,字段名:散文,行号:当前行
				API名称:GetRecordCount,数据源:散文写作/默认表格
				当前行初始是0
				按钮「<」：当前行减1并回填表单与成篇区
				按钮「>」：当前行加1并回填表单与成篇区
				当前行<=1时，「<」不可操作
				当前行>=RecordCount时，「>」不可操作
				当前行==0时，「<」「>」均不可操作
			成篇区下方次按钮：重新抄录（将成篇区纯文本复制到剪贴板）、品读全屏（遮罩层沉浸阅读，仅正文与关闭）
	「文稿馆」页面
		左上显示大标题：文稿馆，说明：已写成的篇章，如一排尚未落锁的书柜
		右上是按钮：+ 去落笔，跳转到「落笔成章」并清空表单，当前行设为0
		搜索框：按写作对象模糊搜索
		筛选器：按题材类型筛选，选项为全部、文化遗址游记、历史人物散文、文明反思、旅行文学、古迹精神探寻
		主体用卡片网格，不用表格。卡片展示字段与表单可编辑字段一致：写作对象、题材类型、现场见闻、个人感悟
			API名称:GetTableCSV,数据源:散文写作/默认表格,字段:[写作对象,题材类型,现场见闻,个人感悟]
			现场见闻、个人感悟在卡片上截取摘要；题材类型显示为印章
			行号为GetTableCSV返回数据的行序（从1开始计数）
			每张卡片有操作按钮：品读、编辑、删除
				品读：当前行=行号，调用GetCellValue获取散文，弹出沉浸式阅读层，文本内容用Markdown主题显示；同时展示写作对象与题材类型；关闭后停留在文稿馆
				编辑：当前行=行号，跳转「落笔成章」，API名称:GetCellValue逐字段获取写作对象、题材类型、现场见闻、个人感悟、散文并回填；可修改前四项后用SetCellValue逐字段更新当前行，无需SubmitRecord
				删除：调用DeleteRecord,数据源:散文写作/默认表格,payload:行号.toString()；删除后刷新卡片列表与首页统计
			点击卡片空白区域等同于品读
			无数据时显示空态与按钮「提笔写下」
		删除、提交、修改成功后，首页统计与最近文稿、文稿馆列表均需刷新
	数据与交互总则
		数据源一律为：散文写作/默认表格
		使用callAppBridge({type:"GetTableCSV", data:"散文写作/默认表格", payload:"写作对象,题材类型,现场见闻,个人感悟"})获取不包含标题行的csv文本
		使用callAppBridge({type:"SubmitRecord", data:"散文写作", payload:"表单数据"})提交记录，表单数据是json文本
		使用callAppBridge({type:"GetRecordCount", data:"散文写作/默认表格"})获取记录数
		使用callAppBridge({type:"GetRecordRow", data:"散文写作/默认表格", payload:"字段名/值"})获取行号（行号从1开始）
		使用callAppBridge({type:"DeleteRecord", data:"散文写作/默认表格", payload:"行"})删除指定行号的记录，行号需要toString()再传给payload
		使用callAppBridge({type:"GetCellValue", data:"散文写作/默认表格", payload:"字段名/行"})获取表单元格的值
		使用callAppBridge({type:"SetCellValue", data:"散文写作/默认表格", payload:"字段名/行/值"})设表单元格的值
		指令流字段「散文」不是用户手工填写的，而是在SubmitRecord提交后由后台AI异步生成；要显示其详情，先GetCellValue，再用Markdown主题显示
		主体列表/卡片展示的字段及GetTableCSV字段必须与表单可编辑字段一致，以便点选后进入编辑
		不得编造表定义中不存在的字段（无ID、无创建日期）
		各页面使用统一水墨书院主题，卡片与按钮具有悬停效果，点击最近列表项必须可查看详情
