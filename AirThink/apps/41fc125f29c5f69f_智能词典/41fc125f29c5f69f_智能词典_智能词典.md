# 智能词典

这是一个面向英语学习、中文中译英和词语辨析的智能词典网页应用。应用使用“词典查询”表，通过任务智能体生成音标、双语释义、词形变化、常用搭配、例句及近反义词。整体采用现代语言学习主题：象牙白背景搭配靛蓝与琥珀色，卡片带轻微纸张纹理和圆角阴影，英文内容使用清晰的衬线字体，中文及界面文字使用易读的 sans-serif。页面响应式适配桌面端和移动端，不需要用户登录页面。

## 页面结构

页面顶部是固定导航栏：

- 左侧显示书本与字母组合 Logo，以及“智能词典”。
- 右侧显示“查词”和“查询历史”两个导航标签，点击平滑切换对应页面。
- 移动端将导航折叠为简洁菜单。

## “查词”页面

页面中央显示主标题“智能词典”，说明文字“查英语、译中文、辨用法，让每个词都真正学会”。

主标题下方是醒目的查词区：

- 输入框标题：查询内容。
- 输入框占位提示：“输入英文单词、中文词语，或两个词进行用法对比，例如：serendipity、坚持、affect 和 effect”。
- 支持按 Enter 发起查询；Shift+Enter 用于换行。
- 输入框下方显示三个可点击的示例标签：“resilient”“一举两得”“historic 和 historical”，点击后填入并立即查询。
- 主按钮标题：“查询”，带搜索图标；查询内容为空时按钮不可用，并显示友好提示“请输入要查询的内容”。
- 查询进行期间禁用重复提交，按钮文字变为“正在查询…”，并展示轻量的词典翻页动画。

表单定义：

表单标题:智能词典查询,表:词典查询,字段:[{字段名:"查询内容",类型:"文本"},{字段名:"查询结果",类型:"指令流",指令类型:"任务智能体",输出类型:"文本"}]

其中“查询结果”是指令流字段，不允许用户手工填写，不在输入表单中显示。用户点击“查询”或按 Enter 后：

1. 使用 `callAppBridge({type:"SubmitRecord", data:"词典查询", payload:"表单数据"})` 提交记录，表单数据必须是 JSON 文本，且只包含 `{"查询内容":"用户输入内容"}`。
2. 提交成功后将当前行设为 1。
3. 后台按照指令描述异步执行：使用技能“7073d60bffe9fa3c_dictionary”，查询并解析查询内容；可处理英文单词、中文中译英或词语用法对比，按技能要求输出详细词典结果。
4. 轮询标题:智能词典查询,表:词典查询,字段:查询结果,输出到:词典结果,等待消息:正在查阅词典并整理释义…
5. 轮询时调用 `callAppBridge({type:"GetCellValue", data:"词典查询/默认表格", payload:"查询结果/1"})`。若内容为空或尚未生成，则间隔合理时间继续轮询；生成完成后停止轮询。
6. 对超时或接口失败提供“重新获取结果”按钮，点击后继续读取当前行的“查询结果”，不能重复新增记录。

结果区域位于查词区下方，初始显示一张引导卡片，包含文案“输入一个词，开始探索它的含义与用法”。查询后：

- 顶部显示本次“查询内容”，旁边提供“复制结果”和“重新查询”按钮。
- “查询结果”必须作为 Markdown 渲染，完整保留标题、列表、表格、粗体、音标、例句等结构。
- Markdown 内容区域需为词典信息优化样式：音标醒目显示，词性使用彩色标签，英文例句与中文译文有清晰层级，词形变化、搭配、近反义词和用法对比可使用分组卡片。
- “复制结果”复制纯文本或 Markdown 全文，并显示短暂的“已复制”反馈。
- “重新查询”保留当前查询内容并再次使用 SubmitRecord 新建查询。
- 不虚构发音音频功能；表中没有音频字段，也不创建额外字段。

## “查询历史”页面

页面标题为“查询历史”，说明文字为“回顾查过的单词、翻译和用法辨析”。右上角提供“+ 新查询”按钮，点击返回“查词”页面并清空输入与结果。

页面顶部提供：

- 搜索框：按“查询内容”在前端即时筛选。
- 排序选项：“最近记录优先”和“最早记录优先”。由于表中没有日期字段，最近记录按表格返回顺序及行号判定，不自行创建日期字段。
- 统计卡片“累计查询”，调用 `callAppBridge({type:"GetRecordCount", data:"词典查询/默认表格"})` 获取记录总数。

历史数据调用：

API名称:GetTableCSV,数据源:词典查询/默认表格,字段:[查询内容,查询结果]

通过 `callAppBridge({type:"GetTableCSV", data:"词典查询/默认表格", payload:"查询内容,查询结果"})` 获取不含标题行的 CSV 文本。必须使用可靠的 CSV 解析方式处理引号、逗号、换行和 Markdown 多行内容，不能简单按换行或逗号切割。为每条记录保留其真实行号，供查看和删除使用。

历史记录以卡片列表呈现：

- 卡片显示“查询内容”和“查询结果”的纯文本摘要；摘要最多显示适当长度，不能破坏原始 Markdown 数据。
- 每张卡片提供“查看详情”“再次查询”“删除”三个操作。
- 点击卡片或“查看详情”时，使用 `callAppBridge({type:"GetCellValue", data:"词典查询/默认表格", payload:"查询内容/行号"})` 和 `callAppBridge({type:"GetCellValue", data:"词典查询/默认表格", payload:"查询结果/行号"})` 获取该记录的完整详情，在侧边抽屉或模态框中用 Markdown 主题显示查询结果。
- “再次查询”将该条“查询内容”带回“查词”页面，并调用 SubmitRecord 发起一条新查询。
- “删除”先显示确认对话框，明确展示将删除的查询内容；确认后调用 `callAppBridge({type:"DeleteRecord", data:"词典查询/默认表格", payload:行号.toString()})`，成功后重新获取列表和总数。取消时不执行任何操作。
- 删除后行号会变化，因此必须重新调用 GetTableCSV 并重建行号映射，禁止沿用旧行号。
- 空状态显示“还没有查询记录”，并提供“开始第一次查询”按钮。

## 当前记录与浏览控制

在词典结果卡片右上角提供上一条与下一条按钮，方便浏览已有记录：

- 当前行初始为 0；新提交记录后当前行设为 1。
- 调用 `callAppBridge({type:"GetRecordCount", data:"词典查询/默认表格"})` 获取总记录数。
- 当前行小于等于 1 时，“上一条”不可用。
- 当前行为 0 或当前行大于等于记录总数时，“下一条”不可用。
- 点击“上一条”或“下一条”后更新当前行，并分别调用 GetCellValue 获取该行的“查询内容”和“查询结果”：
  - `callAppBridge({type:"GetCellValue", data:"词典查询/默认表格", payload:"查询内容/当前行"})`
  - `callAppBridge({type:"GetCellValue", data:"词典查询/默认表格", payload:"查询结果/当前行"})`
- 读取完成后同步更新输入框和 Markdown 结果区域，不提交新记录。

## 数据操作约束

- 只能使用表定义中存在的字段名“查询内容”和“查询结果”，禁止自行添加 ID、日期、状态、收藏、音频等字段。
- 新查询只能使用 SubmitRecord；提交后当前行固定为 1，并轮询异步生成的“查询结果”。
- “查询结果”是指令流字段，不能由用户编辑，也不能在 SubmitRecord 中传值。
- 如果未来提供编辑现有查询内容的入口，必须先确定真实行号，再调用 `callAppBridge({type:"SetCellValue", data:"词典查询/默认表格", payload:"查询内容/行号/值"})`，不能用 SubmitRecord 修改旧记录；本应用默认不提供编辑结果功能。
- 所有加载、空数据、成功、失败和超时状态都要有清晰反馈，接口失败不能导致页面崩溃。
- 所有按钮、导航、示例标签、复制、查询、重试、记录浏览、查看详情、再次查询和删除功能都必须真实实现，不能只制作静态界面。
- 页面统一使用靛蓝语言学习主题，卡片和按钮具有克制的悬停与按压反馈；键盘焦点清晰可见，并保证文本对比度和移动端可用性。
