# 视觉评审派发协议 (主 Agent 专用)

**系统指令**：本文件是主 Agent 调用独立子 Agent 进行质检的“派发说明书”。
> ⚠️ **警告**：你**不需要**通读具体的打分标准和找茬规则，这些都在 [评审手册](reviewer-manual.md) 里。为了节省你的脑容量和防止记忆混乱，你只需把任务打包交给子 Agent，让它去读那本手册并回来向你汇报。

## 1. 什么时候该派发？触发什么模式？

当你完成了一个关键页面、设计方案或改动后，按以下清单触发对应的评审子 Agent：

| 你做了什么改动 | 子 Agent 的提示词 (Prompt) 模板 |
| --- | --- |
| 探索了新界面、完成了整体改版 | `请读取 references/reviewer-manual.md，按照【全新界面与改版评审】标准，对这张截图进行毒舌评审，并给出 1-10 的打分。` |
| 在已有老界面上进行润色/扩展 | `请读取 references/reviewer-manual.md，按照【存量已有界面润色评审】标准，对比提供的现状规范，指出偏离点。不打分。` |
| 小改动、单处间距或颜色微调 | **无需派发子 Agent**，主 Agent 结合上下文自行核对即可。 |

## 2. 派发前，主 Agent 要准备的“交接清单”

调用宿主提供的隔离执行能力时，必须提供以下物料：
- **必给**：当前版本的截图/录屏（注明设备视口）、用户原始任务、设计边界和约束。方向卡里需要评审知道的硬性约束，例如品牌要求每屏出现字标，摘成一句写进约束，不交整张方向卡。
- **如果有**：现有项目的色彩规范、组件约束（存量老项目必须给）。
- **绝对不给**：你的源代码、你心路历程的辩护、之前子 Agent 打过的旧分数（要保证它每次都是盲审）。

截图必须属于当前版本，且能被评审者访问。长页同时提供整页与必要局部；细节图不能替代整体构图。

**动效证据是新界面和改版的必给项，不是“有就给”：**
- 三处基本动效（主操作反馈、一处状态切换、首次出场）各一段 3–5 秒录屏，或开始、中间、结束三帧，写明触发动作。
- 落地页、品牌页、发布页和展览页，再给滚动动效的证据：每段滑动驱动的叙事一段滚动录屏或起点、中段、终点三帧，写明滚动位置；至少两个不同区块的出场录屏或三帧。见 [滚动叙事](scroll-narrative.md)。
- 截图工具的 `report.json` 里有动画探测结果，一并交给评审者；探测报“未检测到动画”时先回去补，不要带着它送审。

交不出某项证据，就照实告诉评审者缺了哪项，评审会按缺陷扣分。没有隔离、能看图的执行者时，主 Agent 按同一手册自检，交付时写明“未独立评审”；没有实际画面时不打视觉分。

## 3. 主 Agent 如何处理子 Agent 的反馈

子 Agent 返回报告后，你是决策者，请按以下原则执行修改：
- **无脑照做项**：子 Agent 列出的“可以直接删掉的无用文字”，**默认照删**（除非这会产生严重的功能歧义）。
- **理性落地**：将子 Agent 的高层视觉要求（如“太挤”、“层级不清”）映射为你对 CSS 间距、字号和阴影的实际调整。但如果子 Agent 提议更改用户硬性锁死的品牌色或大框架，你可以写一句简短理由后拒绝采纳。
- **防止死循环**：如果双方审美意见陷入僵持、来回横跳且无可见收益，保留你认为最佳的版本并停止循环。
