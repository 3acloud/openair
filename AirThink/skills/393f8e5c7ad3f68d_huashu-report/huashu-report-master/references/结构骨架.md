# 结构骨架

科普型的骨架不在这里——它不用「研究问题 → 发现 → 局限 → 结论」，
用的是三幕戏剧骨架，因为它的读者需要动力而不是索引。见 `科普.md`。

## 四种原型的完整组件

### 学术型（Stanford AI Index、Canaries、RAND、CSET、OECD）

```
封面（标题+作者+机构+日期，几乎零设计）
摘要 Abstract（编号事实，200-350 词，能独立读懂）
目录（章节+页码，两级）
1. 研究问题与证据基础
   1.1 本研究相对既有文献的位置 ← 最常被跳过，也最能看出作者懂不懂行
   1.2 这批证据能回答与不能回答的
   1.3 证据分级（不同来源能支撑的结论强度不同）
   1.4 样本框、纳入排除标准、口径统一规则
2-N. 发现（每章一个主题，图表编号 Figure N.M.K）
   每章末：机制分析——为什么会这样，给竞争假说而非单一说法
   末章前：局限性与替代解释，诚实说出没排除掉的
   结论：这些发现合起来意味着什么（必须超出摘要，否则说明只做了汇编）
附录：方法论细节、问卷全文（完整数据表不进附录，见下「附录放什么」）
参考文献
```

**1.1 是学术型报告的分水岭。** 不交代自己相对既有研究的位置，
等于宣称这个领域从你开始。要能回答：印证了什么既有判断、修正了什么、
揭示了什么既有框架没有建模的维度。详见 `研究深度.md`。

关键组件：
- **摘要用编号事实**。Canaries 的写法：「我们记录六个事实。(1)…(2)…(6)…」每条一句，读者可以只引其中一条。
- **局限性单独成节**，不塞进结论的最后一句。
- **图表编号三级**（1.1.13 = 第 1 章第 1 节第 13 图），60 页以上必须三级，否则读者找不回来。

### 论文型（arXiv preprint：measurement / field study）

学术型报告的近亲，但它是要投出去的——体裁、篇幅、语言、生产工具全都不同。
**动手前先读 `论文.md` 的渠道硬约束，那里有能一票否决选题的条款。**

```
标题 + 作者 + 机构 + 日期（arXiv 首页就是封面，零设计）
Abstract（150–250 词，最后一句给出最强的单一数字发现）
1. Introduction（问题 → gap → 本文做什么 → contributions 列表 3–5 条）
2. Related Work（按脉络组织不按论文罗列，每段末句说明本文相对该脉络的位置）
3. Data & Methods（以「他人能复现」为标准：样本框、口径、采集时间、工具）
4. Results（每个发现一小节，Figure/Table 连续编号，图题写结论）
5. Discussion（机制分析，竞争假说形式）
6. Limitations（单独成节，写证据有效性不写工具故障）
7. Conclusion
References（每条都被独立 agent 核实过——见 论文.md）
Appendix（稳健性检验；数据表随投稿包给文件，不排进正文页）
```

关键差异 vs 学术型报告：篇幅 8–30 页；英文写作；LaTeX 不是 HTML；
contributions 必须显式列出（报告靠摘要，论文靠 contributions 被检索和引用）；
Related Work 是必需组件不是加分项。

### 咨询 deck 型（BCG、Deloitte、ICONIQ、KPMG）

```
封面（品牌视觉强，标题就是结论）
目录 = 内容地图（三列：章节 / 覆盖话题 / 页码）
执行摘要（3-5 条，每条一行）
方法论页（整页，样本构成图）
主体：一页一结论
   ├ 小灰字节标签（这页属于哪一节）
   ├ 大号结论句标题（一整句话）
   ├ 图表（自带问题式小标题）
   └ 数据源行
关键行动建议（3-5 条）
封底（联系方式/免责声明）
```

关键组件：
- **目录写成三列内容地图**。ICONIQ 的做法：`Section | Topics Covered | Page`，中间列用 bullet 列出该章覆盖的具体话题。读者扫一眼就知道要不要读，比纯章节名有用十倍。
- **一页一结论是硬约束**。一页塞两个结论，读者两个都记不住。
- **方法论占整页且图形化**。BCG 把 2360 个样本拆成四张小图：职级构成、公司营收分布、行业分布、国别分布。这一页是全报告可信度的地基，不能缩成脚注。

### 调查型（Reuters DNR、Oxford OII、Deloitte 调研）

```
封面
前言（机构负责人署名，说明今年做了什么变化）
方法论摘要（市场数、样本量、field 时间、加权方式）
执行摘要（Key Findings，5-10 条）
主体：双栏正文 + 嵌入图表
   每图下方：问卷原题全文 + Base + N
分市场/分群体章节
附录：完整方法论、各市场样本明细（见下「附录放什么」）
```

关键组件：
- **问卷原题必须随图给**。DNR 的格式：`Q1c. How interested, if at all, would you say you are in news? Base: Total sample across all markets = 97,520.` 少了这行，读者没法判断这个数在问什么。
- **年比年变化要标 pp（百分点）不标 %**。「上升 9pp 到 39%」不写成「上升 9%」——后者有歧义。

### 研报型（Morgan Stanley、UBS、J.P. Morgan）

```
首页：日期时间戳 + 分析师署名 + 一段 thesis
Exhibit 1-N（编号连续，一页可放 2-3 个）
   每个 Exhibit：中性描述标题 + 图/表 + Source 行
分板块/分地区数据表
估值与风险
免责声明（占多页）
```

关键组件：
- **标题用中性描述不用结论**。`Exhibit 27: Industry Groups by Highest Materiality and Exposure` —— 查数的读者要的是索引，不是被说服。
- **表格密度可以很高**。研报读者会逐行看，deck 的留白规则在这里不适用。
- **时间戳精确到分钟**。`February 11, 2026 05:01 AM GMT` —— 研报是有时效的商品。

## 附录放什么

**附录是参考文献表，不是数据表的转印。**

一条来源一行：机构或作者、标题、年份、URL 或 DOI。同一份来源被二十个数字引用过，
它在附录里仍然只出现一次——**附录的长度跟来源数走，不跟数据点数走**。

口径不搬进附录。口径写在用得到它的那一页：正文括号、图注的 N、科普型的侧栏，
而且只写给那些「读者知道了口径会改变判断」的数字（争议值、多口径打架的值、
自己复算的值）。其余数字的口径留在 `数据表.json` 里随交付物一起给——
机器可读的一个文件，比印成一百页 A4 有用。

**体量闸：附录不超过正文的 10%。** 超了就不是严谨，是把工作过程当成了交付物，
和「报告里不写我是怎么做的」是同一条规矩的两个面。

> 实测反例：一本 370 页的书，正文到 242 页，附录 243–370 页——**占全书 35%**，
> 逐条印了 349 个数据点的口径长文（单条口径中位 147 字）。没有任何读者会那样读它。
> 收敛成文献表之后是十几页。

判据一句话：**读者会在什么情况下翻到附录？**
想核某个数字的出处 → 一行文献就够了。
想知道你是怎么算出来的 → 那是方法论节的事，写一段可复用的规则，
不是堆三百条个例。

需要给读者一份能查的数字清单时（研报型、学术型偶尔需要），
印**摘要列**：编号、数值、来源编号。三列一行，不带 basis 长文。

## 篇幅基线（41 份实测）

- 中位数 **34 页**，四分位 27–56 页，范围 7–425
- 政策简报 7–14 页｜deck 27–47 页｜调研报告 30–50 页｜年度旗舰 140–425 页
- 超过 60 页必须有书签大纲（实测只有 56% 的报告做了，做了的那些明显更好用）

## 目录深度

**做了目录的，绝大多数做两级。** 41 份里 23 份有 PDF 书签大纲，这 23 份中 18 份（78%）
是两级或更深，均值 2.04 级。默认按两级做。

> ⚠️ 这条早先写反了，写的是「平均 1.08 级，大多数报告只做一级目录」。
> 两个错：一是 1.08 复现不出来（全体均值 1.146）；二更要命——把均值压低的是
> **18 份根本没有书签大纲的报告**（`toc_depth=0`），那是 PDF 元数据缺失，
> 不是「只做一级」的编辑选择。把缺失当成选择，结论就反了。
>
> 真正反直觉、且可复现的那条事实是另一句：**41 份顶级机构报告里有 18 份没做书签大纲**，
> 读者没法跳章。别学这 18 份。
