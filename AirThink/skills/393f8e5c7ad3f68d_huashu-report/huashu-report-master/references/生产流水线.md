# 生产流水线

规范讲的是「做成什么样」，这一页讲「怎么把它做出来」。
一份 40 页、带十几张图、每个数字都要可追溯的报告，手写 HTML 会在第三次改稿时失控。

## 工作顺序不能颠倒

```
① 定原型和一句话  →  ② 建数据表  →  ③ 写正文  →  ④ 做图  →  ⑤ 渲染自检
```

**②必须在③之前。** 先建数据表再写正文，写的时候每句话都有据可依；
反过来先写正文再补数据，一定会出现「这句话很顺，但我不确定那个数字的口径」——
到那一步再回头查，通常的结果是把这句话留着不查。

## 三文件架构

| 文件 | 职责 | 为什么要分开 |
|---|---|---|
| `数据表.json` | 每个数字的 value / basis（口径）/ n（样本量）/ src（出处）/ verified | 承重层。改正文不动它，改它必须回原文核对 |
| `build.py` | 正文 + CSS + 组装 HTML | 内容和版式在一起，改一处就能重看效果 |
| `render.py` | HTML → PDF、回填目录页码、机械自检 | 渲染逻辑和内容解耦，可跨项目复用 |

`assets/chart.py` 和 `assets/render.py` 可直接复制到项目里改配置用。

### 数据表的字段

```json
{"id": "E1", "value": "19%",
 "basis": "22–25 岁在 AI 高暴露职业的就业水平，低于「若与低暴露同龄人同速增长」的反事实水平",
 "n": "ADP 行政工资单，覆盖数百万美国工人，截至 2026-06",
 "src": "Stanford Digital Economy Lab, Canaries in the Coal Mine?",
 "date": "2026-08-12", "verified": true}
```

`basis` 是最重要的字段，也是最容易糊弄的。写不出一句完整的口径，说明这个数字还不能用。
**规矩：口径不清或拿不到 N 的数据点，一律不进正文。**

### 引用标记

正文里用 `cite("E1")` 生成上标标记，指向数据表。这件事的价值不在于严谨姿态，
而在于它强制你区分两种句子：

- **带标记的**：数字来自被引报告
- **不带标记的**：这是你自己的判断

这个区分做出来之后，读者能自己决定信到哪一层。不做这个区分的综述，
读者只能整体信或整体不信。

## 排版基座

### 版式基座契约：先选页面模式，再动第一行 CSS

呼吸空间出问题（内容顶格、边距忽大忽小、上下不留白）的根因几乎都是同一个：
页边距有两个来源在打架，或者一个来源都没有。契约是——**页边距只有一个权威，开工先声明它是谁**：

| | 模式 A：A4 竖版（默认） | 模式 B：全出血 / deck |
|---|---|---|
| 页边距权威 | `render.py` 的 margin 参数（19/19/17/15mm） | 每页容器自己的 padding |
| HTML 里 | **不写 `@page`，body 不加水平 margin/padding**——写了就是双倍缩进或负溢出 | `@page { margin:0 }` + 固定尺寸 `.page` 容器 + `overflow:hidden` |
| padding 下限 | 不适用（Chromium 保证内容进不了边距） | 横版 deck ≥ 上11/左右16/下12mm；竖版全出血 ≥ 上下16/左右18mm |
| 验收 | `render.py` 几何自检（自动跑） | 同左，把 `MIN_MM` 换成 `MIN_MM_DECK` |

三条铁律：

1. **排版基座不手写，复制 `assets/base.css` 改变量。** 字号、行距、分页规则、表格防粘连
   全部在里面且标注了哪些承重不许改。手写基座是同一份报告里行距从 1.5 漂到 1.9 的直接原因。
2. **模式 B 里 padding 下限是契约不是初始值。** 内容塞不下时砍内容、拆页，不砍留白——
   「这页紧一点」的决定重复五次，报告就没有呼吸空间了。
3. **两种模式交付前都必须跑几何自检。** `render.py` 会把每页渲成灰度图实测四边留白（mm），
   低于阈值直接报页码；封面/章首页这类设计性全出血页会自动跳过并提示肉眼确认。
   「我 CSS 里写了 padding」不算数，实测数字才算。

### 分页容器：让页眉跟着内容跨页

一个 `<div>` 里的内容跨页时，写在 div 顶部的面包屑页眉只会出现在第一页。
40 页的报告里这意味着大半页面没有页眉。

解法是把每一节包成 table，页眉放进 `thead`——
浏览器打印时 `display: table-header-group` 会在每个分页重绘一次表头：

```html
<table class="pagewrap">
  <thead><tr><td><div class="crumb">2.1 广度与深度 | 渗透现状 | 报告名</div></td></tr></thead>
  <tbody><tr><td> …本节全部内容… </td></tr></tbody>
</table>
```

```css
table.pagewrap > thead { display: table-header-group; }
table.pagewrap { page-break-after: always; table-layout: auto; }
```

⚠️ 用了这个方案之后，**所有针对 `table` 的样式都必须排除 `.pagewrap`**，
否则给数据表写的 `table-layout: fixed` 会把版心容器也变成定宽表格，整页布局塌掉。
统一写成 `table:not(.pagewrap)`。

**一个容器 = 一章，不是一节。** 每个容器都带 `page-break-after: always`，
如果一节一个容器，一节内容只有半页时就白扔半页——40 页的报告里能凭空多出五六页留白。
把同一章的所有小节放进同一个容器，章内自然流动。
**章末留白是排版惯例，章内留白是 bug。**

代价是面包屑降到章级（「3 白领工作正在发生什么 | 报告名」而不是「3.2 第一级台阶 | …」）。
对 40 页量级的报告这不亏——小节标题本身就提供了定位。超过 100 页再考虑节级面包屑。

### 分页控制：三条必须写的规则

```css
h2, h3, h4 { page-break-after: avoid; break-after: avoid; }   /* 标题不许被留在页底 */
table:not(.pagewrap) { page-break-inside: auto; }             /* 长表允许跨页 */
table:not(.pagewrap) thead { display: table-header-group; }   /* 跨页时表头重复 */
table:not(.pagewrap) tr { page-break-inside: avoid; }         /* 但单行不许被劈开 */
.fig, .box { page-break-inside: avoid; }                      /* 图表和方框整块搬 */
```

**长数据表千万不要用 `page-break-inside: avoid`。** 一张 20 行的表加了这条，
浏览器会把整张表推到下一页，前一页留下大半页空白——而且这个空白看起来像是你忘了写东西。
正确做法是允许表跨页，靠 `thead` 让表头在每页重复。**表头不重复的跨页表格，读者读不了第二页。**

标题的 `page-break-after: avoid` 同样是硬需求。少了它会出现「一页只有一个小标题，
内容全在下一页」的情况——这是最刺眼的排版错误之一，而且机械自检查不出来
（那一页确实有内容，只是只有五个字）。

### 数据表：列必须有可见边界

这是本流水线里最容易翻车、而且会翻两次的地方。

相邻两列一个右对齐、一个左对齐时，两列的内容会在列缝处贴死。
读者看到的不是两列数据，是一句连起来的假句子：

```
84%尚未围绕 AI 能力重新设计岗位或工作性    ← 数值列 + 口径列糊在一起
调研）Deloitte State of AI in the        ← 样本量列 + 出处列糊在一起
```

**靠加 padding 调不出来**——列窄的时候 padding 会被内容挤掉。可靠的解法只有一个：

```css
table:not(.pagewrap) { table-layout: fixed; }              /* 长内容不撑破列宽 */
table:not(.pagewrap) td, table:not(.pagewrap) th {
    overflow-wrap: anywhere; text-align: left; }           /* 不要两端对齐，行尾顶格会加剧粘连 */
table:not(.pagewrap) td + td { border-left: .5px solid #e8ecee; }   /* 竖分隔线 */
td { padding: 1.8mm 3.4mm; }                               /* 足量 gutter */
```

数值列**不要右对齐**。右对齐会把内容推到列的右边界，正好贴上下一列的起点。
财务报表里右对齐是为了让小数点对齐，在这类混排数据表里它只制造粘连。

### 字号与配色

见 `视觉系统.md`。一条最容易被违反的：**正文用近黑，品牌色只出现在图表、章节标记和强调数字上**。

## 图表

用内联 SVG，不用图表库。原因：

- `file://` 协议下同源本地数据的 `fetch()` 会失败，图表库常踩这个
- 打印时 canvas 会糊，SVG 是矢量
- 40 页报告里图表数量有限（10–20 张），手写 SVG 的精确控制值这个成本

`assets/chart.py` 提供 8 种图型：横条、100% 堆叠条、成对柱（**支持负值**）、
折线（末端直接标注）、大数字、发散堆叠条、斜率图、象限散点。

**负值必须画在零线下方。** 早期版本把负值当成 0 高度，
结果「下降 11%」和「没有变化」在图上完全一样——这是能改变读者结论的错误，
不是美观问题。任何可能出现负值的图，画完先确认零线在哪。

## 渲染与自检

```bash
python3 render.py build.py 报告.html 报告.pdf
```

`assets/render.py` 会循环执行：重建 HTML → 渲染 PDF → 定位每章起始页 → 回填目录页码，
直到页码收敛，最后跑一遍机械自检。

**目录页码不能手写。** 手写的页码在内容一改就错，而这是读者最先发现的错误。

自检分两层。机械层（脚本能查）：图表编号连续与格式统一、目录页码是否渲染出来、
内容极少的页、tuple 渲染痕迹、占位符残留、**逐页实测四边留白**（低于阈值报页码，
并列出「下半页大面积留白」候选页给眼睛复核）。

眼睛层（**脚本查不出来，必须逐页看图**）：

```bash
pdftoppm -png -r 70 报告.pdf 自检/p
```

要看的六类：列缝粘连 / 负值画成零 / 图表被版心切掉 / Y 轴不从零开始 /
图表容器远大于内容留下大片空白 / 跨页时页眉丢失。

**「渲染成 PDF 看过了」不等于「逐页看过了」。** 这份报告的列粘连问题
在第一次自检时就在页面上，我只抽看了四页，漏掉了它，交付后才被指出来。
抽检对排版缺陷无效——排版缺陷不是均匀分布的，它集中在最复杂的那几页（长表格、宽图表、附录）。

## 十一个具体的坑

1. **f-string 里 `{expr,}` 会变成 tuple。** 写 `{fig(...),}` 多打一个逗号，
   渲染出来是 `('<figure…',)` 带括号的 tuple repr。**语法检查发现不了**，
   要么看输出，要么用 render.py 的机械自检（它专门查这个痕迹）。

   同一族的另一个变种更隐蔽：**在普通字符串（忘了写 `f`）里调用组件，
   `{srcbox(...)}` 会原样印在页面上**，把源码印进成品。
   不报错、不告警、语法检查全绿。生成 HTML 后加一句正则扫描即可根治：

   ```python
   import re
   bad = re.findall(r'\{(?:fig|box|pull|bignum|chapter|srcbox)\(', html)
   assert not bad, f"未插值的组件调用：{bad}"
   ```

   长文档里一半段落是 f-string、一半不是，靠眼睛记住哪个是哪个必然会漏。

2. **渲染脚本条件重建 = 看到旧版。** 如果渲染流程写成「页码变了才重跑生成器」，
   改了正文而页码没变时，看到的永远是上一版。**渲染前必须无条件先 build。**

3. **目录页码定位会撞上目录页自己。** 目录里印着所有章节名，
   从第 1 页开始搜正则，每一章都会被定位到目录那一页。必须跳过目录页。

4. **`toc_row(...)` 跨行写会让回填静默失效。** 正则匹配不到跨行的调用，
   页码停在占位值上，而且不报错。所有 toc_row 写在一行内。

5. **页数会抖动。** 目录页码从 1 位变 2 位可能让目录多占一行，
   整体页数跟着变，页码又不准了。要循环到收敛，别只跑一遍。

6. **`table-layout: fixed` 会波及分页容器。** 见上面「分页容器」一节。

7. **只修症状不修根因，同一个 bug 会出现第二次。** 列粘连第一次出现在附录 A，
   我把那一列改成左对齐就过去了；它在附录 B 又出现了一次，因为根因
   （没有列分隔线 + 右对齐贴边）没动。**发现排版缺陷时，先问「同样的结构还出现在哪」。**

8. **选错图型会产生无意义的元素。** 用成对柱画只有一组数据的对比，
   第二根柱子会是 0 高度并标注「0%」——读者会以为那是个真实的零值。
   一组数据用横条，两组才用成对柱。

9. **坐标轴刻度会被格式化成一串相同的数。** `chart.py` 的轴标签默认 `{:.0f}`，
   画 0.90–1.70 这种窄区间时，五个刻度全印成「1, 1, 1, 2, 2」，
   纵轴直接报废。**任何非整数区间的图，画完先看一眼轴标签**——
   机械自检查不出来，它只知道那里有字。

10. **模式 A 下 body 的背景色铺不满页边距。** Chromium 打印时页边距区域是纸白，
    body 背景只覆盖版心。选了暖纸色（`#faf7f2` 这类）就会在每一页四周露出一圈接缝，
    在屏幕上看 HTML 完全正常，导出 PDF 才出现。
    要暖底就走模式 B（`@page margin:0` + 容器自己 padding），
    留在模式 A 就用纯白——**不要试图靠给 `html` 也加背景来绕过，那不生效**。

11. **首字下沉遇到笔画极简的字会变成一根横杠。** 「一」「二」「十」放大三倍做首字，
    读者看到的是一条红线不是一个字；数字开头的「1988 年」会被切成大号「1」＋「988 年」。

    🔄 **这一条以前写成「写作阶段的约束」，实践把它推翻了。** 靠约束二十九个写作
    agent 记住「章首句不许这么开头」，等于把全书一致性押在二十九次记忆上——而这本书
    的章首场景大量以日期开头，等于埋二十九次雷。正确做法是把判断挪进生成器：

    ```python
    def can_drop(para):
        c = para.lstrip()[:1]
        return bool(c) and c not in "一二三十丨〇零①②③" and not c.isdigit() and not c.isascii()
    ```

    写作端因此不需要记这条规则，首字下沉「能用就用、不能用就不用」。
    这是下面「规则该放在哪一层」那一节的样板案例。

    同理，书眉若带通栏横线，会和首字下沉在页面顶端挤成一团——书眉不加线，下方留 11–12mm。

## 规则该放在哪一层：写作端，还是编译器

这是长文档里最值钱的一条，而且它反直觉。

一份 40 页、一个人写完的报告，排版规则写进手册就够了——你自己会记得。
一本 370 页、29 章分给多个 agent 写的书，**写进手册的规则会以肉眼可见的速度漂移**。
实测：同一本书、同一份写作手册，早期批次写的 12 章加粗是每章 3–4 处，
后补的 17 章是 6–36 处。没有人违规，每个 agent 都读了手册——但手册不是强制力。

分界线是这样的：

| 规则 | 放哪 | 为什么 |
|---|---|---|
| 中英文之间不加空格 | **编译器**（pangu 处理） | 纯机械，零判断 |
| 首字下沉能不能用在这个字上 | **编译器**（`can_drop()`） | 判据可写成一行代码 |
| 引用标记 → 上标 + 进附录 | **编译器** | 同上，而且能顺带查「引了数据表里没有的条目」 |
| 加粗一章不超过三四处 | **自检报数**（`longdoc_check`） | 该加在哪句上机器判断不了，但超没超机器数得出来 |
| 各章篇幅别差太多 | **自检报数** | 同上。没有任何单章是「错」的，只能靠比 |
| 章首要写一个具体的人和时刻 | **手册**（没别的办法） | 机器判不了「具体」 |

一条实操判据：**如果一条规则可以写成一个函数或一个计数，就不要留在手册里。**
留在手册里的每一条，都是在赌每个写作者都记得住；而写作者越多、文档越长，
这个赌注的赔率越差。

顺带一个反面细节：空格规范化必须跑在**最终的行内 HTML** 上，不能只跑在原始
markdown 上。「`**平反。** 卡哈尔`」里两个汉字中间隔的是星号不是空格，
在 markdown 阶段规则看不见它；星号一换成 `<em>` 标签，那个空格就露在纸上了。
这个 bug 藏了整整一轮自检才被抓到。

## 上百页量级：额外的五件事

40 页的规范都还成立，但下面这几条只有到了 100 页以上、且分章外包时才会咬人。

**一、目录会跨页，而页码回填只跳过了第一页。** 目录第二页仍然印着章节名，
排在后半段的条目（尤其「附录」这种独占一行的）会被定位到目录第二页上。
实测症状：370 页的书里「附录一」页码回填成 **3**，不报错。
`assets/render.py` 的 `locate()` 已按页眉 crumb 跳过整段目录。

**二、markdown 方言要和生成器对齐一次。** 写作 agent 会自然地用 `###`
写三级标题；如果生成器只认 `##`，井号会原样印在纸上，一本书里 17 处。
**开工前把生成器支持的块类型列给写作端，并且在生成器里对不认识的块抛异常**——
静默透传是最坏的处理方式。

**三、数据表的 `verified` 位必须有人负责。** 调研 agent 只填 value/basis/src，
从不置 `verified`，于是渲染器那条「交付前必须清零⚠未核」的闸永远清不了——
349 条里 341 条挂着红色警告，读者看到的是「这本书每个数字都没核过」。
**开工时就要定：谁在什么条件下有权置 true**（本项目的约定是「亲自读到一手来源」），
核没核完是**数据表文件**里的一位，不是印在纸上的红字——
附录里根本不该有那 349 行（见 `结构骨架.md`「附录放什么」），
所以这个问题的正解是把数据表从附录里拿出去，而不是给它设计一套标注。

**四、逐页自检要换做法。** 300 页一页一张地看是不现实的，也不必要。
把 12 页拼成一张检查表（每页缩到 430px 宽，四列三行，给每格标页码），
30 张图扫完全书。版式缺陷在这个尺度上全都看得见——被切掉的标注、
塌成一列的表格、整页空白、孤儿段；扫到可疑的再单独开全尺寸那一页。
**这仍然是「逐页」，不是抽检**：每一页都进过眼睛，只是分辨率分两档。

**五、文字宽度必须参与几何计算。** 这是本次唯一出现两次的 bug 家族：
横条图把绘图区写死 250 单位、时间轴把居中标注放在最边上的点，
两处都让标注被版心切掉。凡是「给文字预留一块固定空间」的写法都会翻车，
而且翻得没有声响——SVG 不报溢出，机械自检只知道那里有字。
`assets/chart.py` 现在提供 `text_w()` 和 `clamp_x()`，所有 pad/label_w 都由标注反算。

## 篇幅控制

内容写完再调篇幅，不要为了凑页数灌水。**页数不够时能加的只有两种东西**：
真正缺失的横截面分析、关键数字速查表（学术型报告里这一页最实用）。
凑字数的过渡段落会被读者一眼看穿。

**加附录不算加内容。** 把数据表逐条印进书末能瞬间多出上百页，
而这一百页没有一个读者会读——实测一本 370 页的书里附录占了 128 页。
附录的形态与体量闸见 `结构骨架.md`「附录放什么」。
