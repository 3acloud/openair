# 实证样本

huashu-report 的规范不是想出来的，是从这批报告的实物里量出来的。这个目录装着来源清单和量化的解剖数据。

```
samples.md      43份报告的清单：机构、日期、页数、官方链接、许可状态
anatomy.json    41份的量化解剖：页数、尺寸、书签、字体、字号、颜色、图表密度
```

## 为什么不放报告实物

huashu-report 是要 clone 下来装进 agent 的。这批报告 43 份共约 234MB，其中能合法再分发的只有 11 份（93MB）——放进仓库等于让每个装这个 skill 的人，为少数人的需求多下这个体积。所以这里只放来源和量化结果，要原文照 `samples.md` 的链接自己下载。

这也顺带守住了版权。43 份里：

| 档位 | 份数 | 你可以做什么 |
|---|---|---|
| 开放许可（CC BY / BY-NC / BY-ND / OGL） | 11 | 自由使用、再分发，署名即可 |
| 保留所有权利 | 17 | 只能自己读；引用数据点请注明原始出处 |
| 未声明许可 | 15 | 同上——公开发布不等于授权，按版权法默认仍是保留版权 |

**保留所有权利那 17 份里有两份要单独留意**：ICONIQ Capital 的两份每页都印着 Private and Strictly Confidential，IMF 那份页眉是 Not for Redistribution。它们出现在这里只是记录「实证基线量过哪些实物」，不代表可以取用。

## 采集方法

2026年8月，用19个 agent 的并行 workflow 扫了37个渠道，按来源权威／数据原创性／信息增量／时效／可得性等七个维度打分，出74份总榜，再逐份实测能否下到全文 PDF。

落盘标准是 PDF 而非网页快照，且通过内容级校验——标题实词必须与 PDF 前三页的命中率达标。这个判据后来被证明不够严：有 3 份的实词重叠度足以过阈，但内容其实是另一份文件（`samples.md` 的备注列都标了）。

## 解剖数据怎么用

`anatomy.json` 每份记录：页数、页面尺寸与横竖、书签大纲的层级与页码、字体清单与字号分布、正文颜色使用、图表密度代理指标（矢量绘图对象数）。

它是纯量化的，不含报告原文——原始数据里每份报告前 6 页的文本摘录和目录条目的文字都剥掉了。那些 deck 型报告的幻灯片标题本身就是结论句，原文不该由这里代为公开。量化结论不受影响：「目录平均深度」「79%达两级或更深」用的都是层级数据。

skill 里的规范就是从这些字段的中位数与分布里反推的。「正文98%用近黑」量的是每一份的 `text_colors`；「超过60页必须有书签」量的是 `toc_depth`；「品牌色中位只占2.8%字符」也是同一批数据。

想验证某条规范，或者给自己领域的报告立一套基线，都从这里开始量。
