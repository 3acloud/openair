# 美食账号内容创作（meishi-buddy）

一句话价值：给菜名或人群，产出「本地步骤图 + 照着能做的做法 + 一篇贴图短文」，中间该停的地方必须停下来等用户。

---

## 0. 账号定位（所有产出都必须遵守）

- **泛美食号，不细分垂类**。养生、儿童餐、养颜餐、减脂减肥餐、家庭餐、一日三餐、10 分钟快手菜都在同一个号里发。
- **不要因为主题切换人设或风格**：写减脂餐和写儿童餐，语气必须是同一个人在说话。
- 只做「**贴图 + 短文**」，不写长文。
- 每篇产物的固定形态（Markdown 混排）：

```markdown
# <标题>

> 适合：✅减脂 ✅快手（从标签体系中选 1-3 个，别贪多）

<开头一段：这道菜适合谁、有什么好处、一个让人想试的点>

![成品图](00_成品图.jpg)

## 用料
- 主料：…
- 调料：…

## 做法
### 步骤 1
![步骤1](step_01.jpg)
<照着能做的操作描述，说人话>

### 步骤 N
…

<结尾一两句：小贴士或一句互动，别喊口号>
```

**标签体系**（开头「适合」一行从中选）：`养生` `儿童餐` `养颜` `减脂` `家庭餐` `早餐` `午餐` `晚餐` `10分钟快手` `一人食` `下饭` `季节限定`

---

## 1. 三个入口

### 入口 A —— 用户直接给菜名

用户说「番茄炒蛋」「我今天想发番茄炒蛋」：

1. **抓图**：用 `scripts/xcf_recipe.py` 抓下厨房完整菜谱（成品图 + 步骤图 + 用料 + 步骤文案）到本地。
2. **给做法**：把抓到的步骤整理给用户看（步骤图 + 文案对照）。
3. **文案建议**：基于菜品特点和用户账号定位，给出 2-3 个切入角度（如：减脂角度 / 快手角度 / 家庭角度），说明每个角度的结构怎么排，推荐一个。
4. **等用户定方向后写初稿**，用户提意见就改，改到满意为止。

### 入口 B —— 用户给人群或场景，要推荐菜

用户说「受众是学生，推荐几道菜」「夏至了该吃什么」：

1. 结合**人群需求 / 节气 / 功效**（查 `references/food-knowledge.md` 的对应表）推荐 3-5 道菜，每道说清：
   - 为什么适合这个人群（功效依据）
   - 一句话卖点（能直接当标题用的那种）
2. **⛔ 停下来等用户选**。用户挑中一道后，转入入口 A 流程。

### 入口 C —— 用户要一周批量选题

用户说「这周都写减脂的，目标群体是白领减肥人群，帮我排 7 天」：

1. 列出 7 天选题清单，格式：

| 天 | 菜 | 角度 | 一句话卖点 |
|---|---|---|---|
| 周一 | XX | 减脂主食替代 | … |

   排选题注意：荤素搭配、做法难度错开（别连着 7 天硬菜）、早餐/正餐有节奏。
2. **⛔ 停下来等用户确认**。用户逐条对，没问题继续，有问题当场改清单。
3. 确认后**逐篇**按入口 A 展开。每篇之间也停一下，让用户过目再继续下一篇（用户说「连着做」除外）。

## 2. 强制确认节点（不许跳过）

| 节点 | 动作 |
|---|---|
| 入口 B 推荐菜之后 | 停，等用户选 |
| 入口 C 列完 7 天清单之后 | 停，等用户确认，**绝不直接开写正文** |
| 文案初稿给完之后 | 停，等用户提修改意见 |

**不要一口气从选题冲到成稿。** 中间每一站都要停。

## 3. 图片抓取

### 首选：下厨房（稳定可用，已验证）

```bash

python3 <skill_dir>/scripts/xcf_recipe.py <菜名> [--pick N]

# 批量成品图（备选封面图、配图补充）
```

- 输出位置（固定约定）：`/Users/wangzhifeng/Documents/000创作/obsidian/outputs/food-content/<菜名>_recipe/`
- 目录内容：`00_成品图.jpg`、`step_01.jpg ~ step_NN.jpg`、`菜谱.md`（原始数据）、`recipe.json`
- `--pick N` 选搜索结果第 N 个菜谱；换菜谱时用户说「换第 N 个」就带 `--pick N` 重跑
- 技术细节（排障时用）：搜索走桌面版 `www.xiachufang.com/search/`；详情页**必须用 iPhone UA + 移动版域名 `hanwuji.xiachufang.com/recipe/<ID>/`**，桌面版会触发人机验证。图片在 `i2.chuimg.com`，去 query 参数即原图。
- 搜索无结果（脚本输出 `SEARCH_EMPTY`）时：换同义词重试（如「西红柿炒蛋」→「番茄炒蛋」），仍无结果走兜底。

### 兜底：小红书 / 公众号

下厨房搜不到、或用户明确要参考爆款时：

1. **小红书配图和文案参考**：调用已安装的 `global-content-search` skill（关键词 = 菜名 + 主题词，如「番茄炒蛋 减脂」）。
2. **公众号爆款文章参考**：调用 `baokuan-article-analysis` skill（按赛道或关键词）。
3. 兜底来源的图片只作**参考和灵感**（学习构图、角度），优先仍用下厨房的图。兜底文案只拆结构，不照搬文字。

## 4. 文案要求

详细规范见 `references/writing-guide.md`，核心几条：

- **说人话**，别写成菜谱说明书，也别端着说教。像跟朋友聊天「这道菜我强烈建议你试试，因为……」
- 每篇必带的四个信息：**这道菜适合谁 / 有什么好处 / 关键步骤 / 一个能让人想试的点**
- 不同主题侧重不同（减脂讲热量和饱腹感、儿童餐讲营养和挑食、养生讲节气和功效），但**语气永远是同一个人**
- 做法部分用户要看得懂、能照着做：火候、时间、分量写具体，别写「适量」「少许」糊弄（抓到的菜谱有模糊表述就换算成常见单位）
- 合规红线：**不做任何功效/治疗性宣称**（不说「降血压」「治病」「吃了就瘦」），营养好处用「含有 XX 营养素」这类事实性表述兜底

## 5. 交付约定

- 每篇内容最终交付两个东西：**图片目录路径 + 文案 Markdown 文件**（`<菜名>_recipe/文案.md`，与图片同目录，图片用相对路径引用，发帖时直接可用）
- 涉及多篇（一周选题）时，额外在 `food-content/` 下生成 `选题_YYYYMMDD.md` 记录清单和进度
- 交付时用 present_files 展示文案 md 和关键图片

## 6. 可点击交付（强制）

每次交付时，回复正文里**必须**带上可点击的 `file://` 链接，让用户一点就打开：

```markdown
📂 [打开文件夹](file:///Users/wangzhifeng/Documents/000创作/obsidian/outputs/food-content/乌鸡汤_recipe)
📄 [查看文案.md](file:///Users/wangzhifeng/Documents/000创作/obsidian/outputs/food-content/乌鸡汤_recipe/文案.md)
🖼️ [看成品图](file:///Users/wangzhifeng/Documents/000创作/obsidian/outputs/food-content/乌鸡汤_recipe/00_成品图.jpg)
```

规则：
- **文件夹链接**（`file://` + 目录绝对路径，无末尾斜杠）——点击直接在访达/Finder 打开该目录
- **文案.md 链接**——点开直接看成品文案
- **成品图/首图链接**——快速预览封面
- 路径里有中文/空格不影响，`file://` 后直接拼绝对路径即可；链接文字用「打开文件夹/查看文案/看成品图」等固定短语，别只贴裸路径
- 交付多篇（一周选题）时，每个菜谱目录各给一组链接，最好列成清单
- present_files（展示卡片）照常调用，file:// 链接是**补充**，两者都要有
