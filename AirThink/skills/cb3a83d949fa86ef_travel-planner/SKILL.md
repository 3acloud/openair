# Travel Planner

基于 AI 生成结构化旅行行程规划，覆盖目的地研究、每日行程、住宿、美食、交通、预算六大板块，并支持生成可分享的旅行数字卡片。

**零配置，零依赖**：直接输入目的地和天数即可生成完整行程，无需任何 API Key、外部服务或命令行操作。

## 安全与隐私声明

- 本技能不收集、不存储、不上传任何用户数据
- 不请求网络外的文件系统权限，仅在用户明确要求时写入行程文件
- 不执行任何命令行命令（Bash），不调用任何外部 API
- 生成的行程内容完全由 AI 内置知识库产出，不依赖第三方服务
- 所有推荐（酒店、餐厅、价格）均为 AI 估算，不涉及实时数据采集

## 1. 快速开始（30 秒上手）

一句话输入目的地和天数，即可获得完整行程：

> "帮我规划一个东京 3 天的行程"

系统会自动询问缺失信息（如日期、预算、风格），然后输出 6 大板块完整行程，并在最后提示：

> ✅ 行程已生成！需要我把这份行程做成一张精美的旅行数字卡片吗？可以分享到朋友圈/小红书/微信。

## 2. 能力边界（明确支持与不支持）

### 支持

- 规划全球任意城市的多日旅行（1-14 天）
- 按预算档次筛选方案（经济型 / 舒适型 / 豪华型）
- 根据兴趣定制（美食、文化、自然、购物、亲子）
- 生成可直接分享的行程文档（Markdown 格式）
- 生成可分享的旅行数字卡片（HTML 格式，可截图保存）
- 中英双语输出，自动匹配用户语言

### 不支持（明确声明，避免误用）

- ❌ 实时订票/下单 — 只提供推荐链接，不直接预订
- ❌ 实时交通导航 — 提供路线建议，不含实时路况
- ❌ 实时价格查询 — 价格为 AI 估算参考值，非实时抓取
- ❌ 个人行程管理/日历同步 — 不与 Google 日历/苹果日历集成
- ❌ 签证代办 — 只提供签证要求信息，不代办申请
- ❌ 多人协作编辑 — 单次生成，不支持多人同时编辑

## 5. 详细工作流程（5 步）

### Step 1: 收集需求（含输入格式自动规范）

AI 会主动询问以下信息，同时自动纠正输入格式：

| 字段 | 是否必填 | 示例 | 缺省处理 | 格式不规范时的自动处理 |
|---|---|---|---|---|
| 目的地 | 必填 | 东京 / Tokyo | 无法继续，必须提供 | 自动识别中英文混用，如"去东京玩"→提取"东京" |
| 天数 | 必填 | 3 天 | 无法继续，必须提供 | 自动解析数字，如"三天"→3，"3.5天"→提示取整数 |
| 旅行日期 | 推荐 | 2026-08-10 至 08-13 | 默认不指定 | 自动解析多种日期格式，如"8月10号"→2026-08-10 |
| 预算范围 | 选填 | 5000-8000 CNY | 默认舒适型 | 自动提取数字，如"预算一万"→10000 CNY |
| 旅行风格 | 选填 | 经济 / 舒适 / 豪华 | 默认舒适型 | 自动映射同义词，如"便宜"→经济型，"高端"→豪华型 |
| 同行人数 | 选填 | 2人 / 带小孩 | 默认按单人规划 | 自动解析，如"一家三口"→3人 |
| 兴趣偏好 | 选填 | 美食、文化 | 默认综合体验 | 自动提取关键词，如"想吃好吃的"→美食 |
| 饮食限制 | 选填 | 素食 / 清真 | 默认不限制 | 自动识别，如"不吃肉"→素食 |

**输入格式不规范时的处理策略**：

- 如果用户输入模糊（如"想去海边玩几天"），先确认具体目的地和天数
- 如果用户输入包含多余信息（如"帮我规划一下东京旅行，大概三天左右吧，预算大概五六千"），自动提取关键信息并确认
- 如果用户输入包含不可能的组合（如"东京 1 天 14 个景点"），自动提示合理范围并重新规划
- 如果目的地过于宽泛（如"去日本玩"），提示用户指定具体城市

### Step 2: 信息补充（含网络异常降级）

如有网络访问，自动搜索补充：

- 目的地当季天气和旅行提示
- 旅行期间当地节日/活动
- 签证要求和入境限制
- 汇率参考

**网络异常时的降级策略**：

- 如果搜索超时或失败，跳过实时信息，直接基于 AI 知识库生成行程
- 在行程中标注"天气/汇率信息可能非实时，建议出发前确认"
- 不阻塞主流程，用户无需手动重试

### Step 3: 生成行程（AI 直接生成，无需外部 API）

**核心机制**：AI 直接利用内置模型能力生成结构化行程，不需要任何外部 API Key 或配置。

按标准格式输出，包含 6 大板块：

1. **总览** — 目的地简介、最佳季节、核心亮点、签证提示
2. **每日行程** — 分上午/午餐/下午/晚餐/晚间，每项含地点、活动、建议时长、预估花费
3. **住宿** — 每晚 2-3 个选项（不同价位），含区域、评分、特点
4. **美食** — 每天推荐餐厅，含菜系、位置、人均、招牌菜
5. **交通** — 城际往返方案 + 市内交通卡/打车建议
6. **预算** — 分项明细 + 总预算 + 人均

**生成后自动验证**：

- 检查 6 大板块是否完整（缺项自动补全）
- 检查每日行程天数是否与用户要求一致
- 检查预算明细合计是否等于各分项之和
- 检查是否有明显不合理推荐（如推荐已关闭景点）

**异常处理策略**：

- 如果生成过程中遇到模型限制或超时，自动重试一次（带提示"正在重新生成，请稍候..."）
- 如果重试仍失败，输出简化版行程（仅包含总览+每日行程+预算），并说明原因
- 所有错误提示均为中文，不使用英文技术术语

### Step 4: 提示生成数字卡片（含实拍图）

行程生成完成后，AI 主动提示用户：

> ✅ 行程已生成！需要我把这份行程做成一张精美的旅行数字卡片吗？
> 卡片包含：目的地实拍大图、精选景点照片、每日行程缩略图、总预算，可以截图分享到朋友圈/小红书/微信。
> 回复"生成卡片"即可。

**用户回复"生成卡片"或"好"/"可以"/"yes"后**：

1. 从已生成的行程中提取关键数据：目的地、天数、每日主题、核心景点、预算
2. **获取实拍图**（通过 WebSearch 搜索图片 URL）：
   - 头部大图：搜索 "{目的地} city skyline photo" → 获取 1 张城市实拍 URL
   - 精选景点图：从行程中选取 4 个代表性景点 → 逐一搜索 "{景点名} {目的地} photo" → 获取 4 张 URL
   - 每日缩略图：从每天行程中选取 2-3 个核心景点 → 搜索实拍图 URL
3. 根据 `references/card_format.md` 规范和 `assets/travel_card_template.html` 模板生成 HTML 卡片
4. 卡片样式根据目的地自动配色（如东京→紫红、巴黎→蓝白、巴厘岛→绿金）
5. 所有 `<img>` 标签添加 `onerror` 降级：图片加载失败时自动隐藏或替换默认图，不影响卡片展示
6. 输出 HTML 代码块，用户可直接在浏览器中打开预览并截图

**图片加载降级策略**：
- 头部大图失败 → 替换为 Unsplash 随机旅行图
- 景点图失败 → 隐藏该图片，不显示空白
- 所有图片均使用 `object-fit: cover` 确保比例统一

**用户拒绝或忽略提示时**：不强制生成，继续后续对话。

### Step 5: 优化迭代

行程或卡片生成后，用户可要求调整：

- "把 Day 2 换成购物路线" — 替换单日行程
- "预算降到 5000 以内" — 全局压缩预算
- "推荐一家怀石料理" — 补充特定美食
- "加入富士山一日游" — 增加周边景点
- "卡片换个颜色" — 重新生成不同配色的卡片
- "卡片换张景点图" — 替换卡片中的实拍图
- "卡片加上二维码" — 在卡片中添加行程详情链接

## 7. 反模式与常见问题（FAQ）

### 7.1 这些用法是错的

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 只给目的地不给天数 | AI 无法知道要安排几天 | 总是提供"目的地 + 天数"，如"东京 3 天" |
| 要求"最便宜"但不设预算上限 | 可能输出不可行的方案（如睡车站） | 给出具体预算范围，如"预算 3000 元" |
| 同一天塞 8 个景点 | 行程过于紧凑，实际无法执行 | 每天安排 3-4 个主要活动，留缓冲时间 |
| 跨城市当天往返却不说明 | 交通时间可能占满一天 | 明确说明"跨城市"，AI 会安排合理交通 |
| 让 AI 直接帮你订酒店/机票 | 本技能只生成推荐，不执行预订 | 拿到推荐后，自行去 Booking/携程/飞猪下单 |
| 输入"去日本玩" | 目的地太泛，日本包含多个城市 | 指定具体城市，如"东京"或"大阪" |
| 要求生成超过 14 天的行程 | 内容过长，质量下降 | 分段规划，如"关西 7 天 + 关东 7 天" |

### 7.2 常见问题

**Q: 没有网络，行程还能生成吗？**

A: 可以。有网络时会补充实时天气和汇率，无网络时依赖 AI 内置知识库生成行程，内容依然完整。无需手动重试，AI 会自动降级处理。

**Q: 行程里的价格是实时的吗？**

A: 不是。价格为 AI 估算的参考值，实际预订时请以平台实时价格为准。住宿价格通常浮动 ±30% 为正常范围。行程末尾会标注"价格仅供参考"。

**Q: 可以生成英文行程吗？**

A: 可以。输入英文即输出英文行程，输入中文即输出中文行程。目的地名称会同时提供当地语言 + 英文。

**Q: 支持多少天的行程？**

A: 1-14 天效果最佳。超过 14 天建议分段规划（如"日本关西 7 天 + 关东 7 天"）。

**Q: 生成失败时怎么办？**

A: 如果生成失败，AI 会自动重试一次。如果仍失败，会输出简化版行程（总览+每日行程+预算），并说明原因。所有错误提示均为中文，无需手动配置任何参数。

**Q: 数字卡片是什么格式？怎么使用？**

A: 卡片为 HTML 格式，包含目的地实拍大图、精选景点照片、每日行程缩略图。生成后复制代码到 `.html` 文件，用浏览器打开即可预览。可直接截图保存为图片，分享到朋友圈/小红书/微信。

**Q: 卡片里的实拍图从哪里来？加载失败怎么办？**

A: 图片由 AI 通过 WebSearch 搜索景点实拍图 URL 获取。每个图片都有降级处理：头部大图失败时替换为默认旅行图，景点图失败时自动隐藏，不影响卡片整体展示。打开卡片时需联网加载图片。

**Q: 数字卡片可以自定义吗？**

A: 可以。生成后可以要求修改：换颜色、调整内容、添加/删除板块。也可以直接修改 `assets/travel_card_template.html` 模板。

**Q: 输出的 Markdown 可以直接复制到飞书/Notion/公众号吗？**

A: 可以。Markdown 表格和标题格式在主流平台都兼容。如果目标平台不支持表格，可以要求 AI 转换为列表形式。

**Q: 需要配置 API Key 吗？**

A: **不需要。** 直接在对话中输入即可，AI 会利用内置能力生成行程和卡片。本技能附带了一个可选的独立脚本（`scripts/generate_itinerary.py`），仅开发者批量生成时才需要，且需自备 API Key。

**Q: 数据安全吗？**

A: 安全。本技能不收集、不存储、不上传任何用户数据。行程内容完全由 AI 内置知识库生成，不涉及第三方数据采集。

## 9. 语言与货币

- **语言**：用户说中文 → 输出中文；用户说英文 → 输出英文
- **货币**：默认人民币 ¥；用户指定其他货币时按指定货币输出
- **目的地名称**：同时提供当地语言 + 中文/英文，如"东京 Tokyo"、"巴黎 Paris"
- **卡片语言**：与行程语言一致
